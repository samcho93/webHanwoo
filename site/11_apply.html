새 영상 적용과 확장

만든 시스템을 다른 축사·다른 카메라 영상에 적용하는 방법과, 더 높은 정확도를 위한 확장 방향을 정리합니다.

1. 다른 영상에 바로 적용

# 단일 영상
python run_activity.py D:/farm2/cam1_0601.mp4
# 폴더 전체, 결과 위치 지정
python run_activity.py D:/farm2 --out D:/farm2_results
# 소 체격이 다르면 원근 기준 체고 변경 (예: 송아지 위주 1.0m)
python run_activity.py D:/farm2 --cow-height 1.0
# 대시보드·CSV 만 빠르게 (영상 렌더링 생략)
python run_activity.py D:/farm2 --no-video

원근 모델(h(y))은 영상마다 자동으로 적합되므로 카메라 위치가 달라도 별도 설정이 필요 없습니다.

2. 새 축사에서 정확도가 떨어질 때: 재학습 루프

새 영상 수집
→
prepare_dataset.py
자동 라벨
→
(선택) CVAT 검수
→
train.py
기존 hanwoo 모델에서 시작
→
run_activity.py
python scripts/prepare_dataset.py D:/farm2 --out data/farm2_ds --val cam1_0601
python scripts/train.py --data data/farm2_ds/hanwoo.yaml --model models/hanwoo_yolo11s.pt --epochs 40
여러 농장의 데이터셋을 합치려면 hanwoo.yaml 의 train: 에 이미지 폴더를 리스트로 여러 개 적으면 됩니다.

3. 파라미터 튜닝 가이드

현상조정
멀리 있는 소를 자주 놓침imgsz 1280, conf 0.2
ID 가 너무 자주 새로 생김추적기 new_track_thresh↑, track_buffer↑, 정합 stitch_max_gap_s↑
서로 다른 소가 같은 ID 로 합쳐짐stitch_max_cost↓, stitch_app_weight↑
서 있는 소가 ‘Active’ 로 많이 나옴rest_speed↑ 또는 motion_energy_active↑ (조명 깜빡임·카메라 노이즈가 큰 경우)
처리 속도가 느림추적기 with_reid: False, imgsz 640, 영상 렌더링 생략(--no-video)

4. 확장 방향

(1) 호모그래피로 정확한 거리

import cv2, numpy as np
img_pts   = np.float32([[150,190],[700,180],[840,300],[20,310]])   # 화면상 바닥 네 모서리
world_pts = np.float32([[0,0],[20,0],[20,12],[0,12]])              # 실제 좌표(m)
Hm = cv2.getPerspectiveTransform(img_pts, world_pts)
# 소의 발 위치(bbox 아래 중앙)를 바닥 좌표(m)로
foot = np.float32([[[cx, y2]]]); world = cv2.perspectiveTransform(foot, Hm)

바닥 면이 평면이라는 가정 하에 픽셀 → 실제 m 로 정확히 변환됩니다. 발이 펜스에 가리는 경우가 많으면 bbox 하단 대신 원근모델로 추정한 발 위치를 쓰세요.

(2) 여러 날에 걸친 개체 식별

레슨 08의 ReID 는 한 영상 안에서 N 마리를 구별합니다. 날짜가 다른 영상 사이에서 같은 소를 같은 번호로 부르려면, 각 소의 대표 임베딩을 “개체 대장”으로 저장해 두고 새 영상의 N 개 슬롯을 Hungarian 으로 대장에 대응시키면 됩니다. 귀표(이표) 번호 OCR 과 결합하면 실제 이력번호와 연결할 수도 있고, 소수 구간을 사람이 확인해 ReID 학습 데이터에 추가하면 정확도가 더 올라갑니다.

(3) 자세·행동 인식

누워 있음(lying)/서 있음(standing)/섭식(feeding) 을 클래스로 나눠 라벨링해 YOLO 를 다중 클래스로 학습하면, 반추·휴식 시간 같은 생리 지표를 직접 측정할 수 있습니다.

(4) 실시간 운영 (RTSP 카메라)

cv2.VideoCapture("rtsp://...") 로 IP 카메라 스트림을 읽고, 온라인 추적 + 일정 주기(예: 10분)마다 오프라인 정합·집계를 수행하여 DB(예: SQLite, InfluxDB)에 저장, 대시보드를 주기적으로 갱신하는 구조로 확장할 수 있습니다.

(5) 이상 개체 알림

개체별 일일 활동지수의 기준선(최근 7일 평균 ± 표준편차)을 만들고, 크게 벗어나면 알림: 활동 급증 → 발정 의심, 활동 급감 → 질병·파행 의심.

마치며

이 강좌에서 만든 것은 검출 → 추적 → 정합 → 측정 → 시각화로 이어지는 완결된 파이프라인입니다. 각 단계가 독립된 모듈이므로, 더 좋은 검출기·추적기·지표가 생기면 해당 모듈만 교체하면 됩니다.
